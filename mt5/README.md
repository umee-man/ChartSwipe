# ChartSwipe Sync — советник для MetaTrader 5

Советник рисует на графике MT5 уровни, которые вы поставили в приложении ChartSwipe:
поддержка/сопротивление — горизонтальные линии, зона — закрашенный прямоугольник.
Изменения появляются в терминале примерно за 5–10 секунд.

**Советник не торгует.** В коде нет ни одной торговой функции (нет `OrderSend`, `CTrade`,
работы с позициями) — это требование проп-фирм к сторонним советникам. Он только читает
уровни с сервера и рисует объекты.

## Установка

1. В MT5: **Файл → Открыть каталог данных**, перейдите в `MQL5\Experts\`.
2. Скопируйте туда **оба** файла: `ChartSwipeSync.mq5` и `ChartSwipeCsv.mqh` (в одну папку).
3. Откройте файл в MetaEditor (F4) и нажмите **Компилировать** (F7) — появится `ChartSwipeSync.ex5`.
   Либо в терминале: окно «Навигатор» → «Советники» → ПКМ → «Обновить».
4. Перетащите **ChartSwipeSync** из «Навигатора» на график нужного символа
   (например, `BTCUSD.r`).

«Алготрейдинг» и «Разрешить алгоритмическую торговлю» включать **не нужно**: советник
работает и с выключенной алготорговлей (таймер и сетевые запросы от неё не зависят,
блокируются только торговые операции, которых здесь нет). Единственное обязательное
разрешение — адрес API в списке WebRequest (ниже).

## Разрешите адрес API (обязательно)

MT5 блокирует сетевые запросы к адресам, которых нет в списке разрешённых.

1. **Сервис → Настройки → Советники**.
2. Включите **«Разрешить WebRequest для следующих URL»**.
3. Добавьте адрес API, тот же, что во входном параметре `ApiUrl`, например
   `https://api.example.com` (без `/v1` и без пути).
4. Нажмите **OK**. Перезапускать советник не нужно — на следующем опросе он подключится сам.

Если адрес не добавлен, на графике будет подсказка, а во вкладке «Эксперты» — ошибка **4014**.

## Входные параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ApiUrl` | `https://api.example.com` | Адрес API ChartSwipe, без `/v1`. Только `https://` — иначе советник не запустится (исключение для разработки: `http://localhost` и `http://127.0.0.1`). |
| `ApiKey` | пусто | API-ключ из приложения: **Интеграции → MT5 → Создать ключ**. Показывается один раз — сохраните его. Пробелы и перевод строки по краям обрезаются. |
| `SymbolSuffix` | пусто | Суффикс символов вашего брокера: `.r`, `m`, `-P` и т.п. Уровень `BTCUSD` с суффиксом `.r` рисуется на графике `BTCUSD.r`. |
| `ShowAllSymbols` | `false` | `true` — рисовать на этом графике уровни **всех** символов (для отладки). Обычно `false`. |

Какой символ MT5 соответствует символу из приложения (например, `BTCUSDT` → `BTCUSD`), задаётся
на сервере (маппинг символов). Советник только добавляет `SymbolSuffix`.

## Как это работает

- Каждые 5 секунд: `GET {ApiUrl}/v1/sync/mt5?since=<курсор − 5 с>` с заголовком `X-API-Key`.
  Небольшое перекрытие в 5 секунд нужно, чтобы не потерять две правки в одну секунду;
  повторно пришедшие строки применяются без изменений.
- Сервер отвечает CSV: первая строка `#cursor,<время>`, затем заголовок и строки уровней,
  изменившихся после `since` (в том числе удалённые).
- **Лимит сервера — 30 запросов в минуту на ключ.** Один график = 12 запросов в минуту,
  поэтому с одним ключом запускайте советник **не больше чем на 2 графиках**.
- При ошибках (HTTP 429, 5xx, нет сети) советник делает паузу и увеличивает её:
  10 → 20 → 40 → 60 с (или сколько попросил сервер в `Retry-After`). После первого
  успешного ответа снова опрашивает каждые 5 секунд.
- Объекты называются `CS_<id уровня>`. Существующие объекты обновляются на месте,
  удалённые в приложении уровни (`deleted=1`) удаляются с графика. Чужие объекты
  (без префикса `CS_`) советник не трогает.
- При каждом запуске (перезапуск терминала, смена параметров или символа) советник
  загружает **полный снимок** уровней одним запросом и убирает с графика устаревшие
  объекты `CS_`. Так график всегда совпадает с сервером, даже если сменились `ApiUrl`,
  `ApiKey` или `SymbolSuffix`.
- Курсор после каждой синхронизации записывается в глобальную переменную терминала
  `CS_cur_<хеш источника>_<id графика>` (F3 → «Глобальные переменные») — у каждого графика своя.
- При снятии советника с графика нарисованные уровни **остаются**.
- Объекты нельзя выделить мышью: уровни редактируются в приложении, а не в MT5.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| Ошибка **4014**, подсказка «WebRequest запрещён» | Добавьте `ApiUrl` в разрешённые (см. выше). Адрес должен совпадать по схеме и домену. |
| **HTTP 401 / 403** | Ключ неверный или отозван. Создайте новый в приложении и вставьте в `ApiKey`. |
| **HTTP 429** | Слишком частые запросы: советник запущен больше чем на 2 графиках с одним ключом. Уберите его с лишних графиков; пока лимит превышен, советник сам делает паузы. |
| «ApiUrl должен начинаться с https://» | Укажите адрес с `https://`. Обычный `http://` разрешён только для `localhost` / `127.0.0.1`. |
| **HTTP 5xx** / «Нет связи с сервером» | Проблема сервера или сети; советник повторит запрос сам. |
| Советник запущен, но уровней нет | Проверьте `SymbolSuffix` и маппинг символов: имя уровня + суффикс должно точно совпадать с символом графика. Временно включите `ShowAllSymbols=true`, чтобы проверить, что уровни вообще приходят. |
| Уровни «зависли» после ручного удаления объектов | Перезапустите советник (например, откройте его свойства и нажмите OK) — он загрузит полный снимок. |
| В тестере стратегий ничего не рисуется | Ожидаемо: MT5 не выполняет WebRequest в тестере. |

Все сообщения советника — во вкладке **«Эксперты»** окна «Инструменты» (Ctrl+T).

## Тесты (для разработчиков)

Разбор CSV, правила курсора, бэкофф и проверка входных параметров вынесены в
`ChartSwipeCsv.mqh` (чистые функции). Тесты — скрипт `tests/ChartSwipeCsvTest.mq5`:

1. Скопируйте `ChartSwipeCsv.mqh` в `MQL5\Scripts\ChartSwipe\`, а `tests\ChartSwipeCsvTest.mq5` —
   в `MQL5\Scripts\ChartSwipe	ests\` (скрипт подключает `../ChartSwipeCsv.mqh`).
2. Скомпилируйте: `MetaEditor64.exe /compile:"<путь>\ChartSwipeCsvTest.mq5" /log`.
3. Запустите скрипт на любом графике демо-счёта. Во вкладке «Эксперты» — `PASS`/`FAIL`
   по каждой проверке и итог `ChartSwipeCsvTest: N passed, 0 failed -> OK`.
